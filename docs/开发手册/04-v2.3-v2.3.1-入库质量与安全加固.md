# 04 · v2.3~v2.3.1 入库质量与安全加固（2026-08-25 / 08-30）

> 目标：一手抓「入库质量」（清洗 + 同名覆盖），一手还清安全债——依据 2026-08-27 外部代码评审报告（7.8 分）落地一整批安全修复。

## 一、阶段目标

1. 上传文本两阶段清洗，提升切片与检索质量；
2. 同名文档增量覆盖而非重复堆积；
3. 评审报告中的 🔴 严重项全部闭环，🟡 中等项尽量闭环。

## 二、关键动作与决策

### 1. 两阶段清洗（v2.3.0，`cleaner.py`）

- **基础清洗**：统一换行符、去零宽/不可见控制字符、规范化标点、压缩连续空行；
- **结构清洗**：去页眉页脚（重复短行/页码/分隔线）、去目录页（「…」跳转行）、合并被硬换行拆散的中文段落、去 `| --- |` 表格分隔行；
- 清洗后为空直接丢弃；内容相同的相邻分片去重。**决策**：清洗放在切片之前——脏文本切片后每片都脏，事后无法补救。

### 2. 同名覆盖 + 自然排序

- 上传同名文件按文件名定位旧 `doc_id`，**分片级增量更新**（复用未变化分片，仅增删变更部分）；`content_hash` 相同直接跳过防重复；
- 前端结果三态：`✅ 清洗入库 / ♻ 覆盖更新 / ⏭ 跳过`；
- 文档列表改按文件名前导数字自然排序（001→056），24h 内更新显示标记——为批量入库对账服务。

### 3. 安全修复批次（v2.3.1，评审驱动）

| 严重度 | 问题 | 修复 |
|--------|------|------|
| 🔴 | 反馈管理接口匿名可读可改 | 补 `require_role("admin")`；`/api/qa/stats` 加登录 |
| 🔴 | 密码单次 SHA-256 | 升级 **scrypt**（N=2^14, r=8, p=1），**存量哈希惰性迁移**（旧格式登录成功即自动重哈希，用户无感），密码最少 8 位 |
| 🔴 | 默认密钥可带毒上线 | 启动自检：认证开启 + JWT_SECRET 为默认值**拒绝启动**；change-me/admin123 强警告 |
| 🟡 | 上传重活阻塞事件循环 | OCR/清洗/切片/入库移入 `run_in_threadpool`；新增 50MB 上限（413） |
| 🟡 | 注册接口 role 可自封 admin | 公开注册强制 user，role 仅登录 admin 可指定 |

- **原子写推广**：`users.json` → `sessions.json` → `knowledge_bases.json` → `feedback.jsonl` 全部改临时文件 + `os.replace`；`chat_history` 锁粒度统一到用户级，配 **20 线程并发写测试**锁定；
- **匿名面收紧**：`/api/knowledge/stats`、`/api/model/config` 加登录（原先可读服务器路径与模型配置）；`kb_id` 校验 `^[a-zA-Z0-9_-]{1,64}$` 防畸形 ID 拼坏 Chroma collection 名；
- 测试 42 → 46（新增 `test_security.py` 8 例）。

### 4. start.bat 闪退（第二次踩同一个坑）

- 根因：脚本里混入 UTF-8 中文注释，Windows cmd 以 GBK 解析打碎脚本结构，python 被拼上乱码参数立即退出；
- 修复：恢复**纯 ASCII**（校验 0 个非 ASCII 字节）+ 失败分支加 `pause`（报错停留可见，不再无声闪退）；
- 顺带：启动脚本接管「自动打开浏览器」——隐藏 PowerShell 进程轮询 TCP 端口（最多 30s）就绪后拉起默认浏览器；`main.py` 不回加浏览器逻辑，避免双重打开。

## 三、产出物

`cleaner.py` 清洗流水线；同名覆盖增量入库；scrypt + 惰性迁移 + 启动安全自检；全量原子写；`test_security.py`；纯 ASCII 的 `start.bat`（含端口探测自动开浏览器）。

## 四、教训与规约

1. **外部评审值得花钱/花时间**：自己写的代码对自己「看起来没问题」，评审视角专找鉴权缺失、默认密钥、竞态这类盲区——本批次 7 个严重项全部来自评审；
2. **惰性迁移是升级密码哈希的正确姿势**：强制全员重置密码会把安全升级变成事故；
3. 原子写（临时文件 + `os.replace`）是 JSON 持久化的默认写法，进程随时可能被杀；
4. **`.bat`/`.sh` 启动脚本永远只写 ASCII**——这个坑踩过两次才固化成规约，同类问题两次出现就该上升为规则；
5. 失败分支必须 `pause` 或留日志：无声闪退是最浪费排查时间的故障形态。
