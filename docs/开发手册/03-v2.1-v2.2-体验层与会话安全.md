# 03 · v2.1~v2.2 体验层与会话安全（2026-08-20）

> 目标：在 v2.0 的架构底座上补「检索质量」与「用户层」——查询改写 / 上下文压缩 / 热缓存三件套提升回答质量，对话历史与个人记忆补齐用户数据层；同日发现并修复一个**会话越权漏洞**。

## 一、阶段目标

1. 检索增强：口语化问题改写、超长上下文压缩、高频问题缓存；
2. 可运营：Token 用量监控、用户反馈闭环（低分自动标记待优化）；
3. 用户数据层：每用户独立的对话历史与个人记忆；
4. 补一个被忽略的安全洞：会话隔离。

## 二、关键动作与决策

### 1. 检索增强三件套（v2.1.0）

- **查询改写**（`query_rewriter.py`）：LLM 改写口语化问题 + 规则同义词扩展兜底（「咋请假」→「如何申请请假 事假 病假 年假 调休」），`QUERY_REWRITE` 可开关；
- **上下文压缩**（`context_compressor.py`）：双模式——LLM 摘要压缩（质量优先）/ 规则截断压缩（离线兜底），Token 预算默认 6000（`CONTEXT_TOKEN_BUDGET`）；
- **热查询缓存**（`cache.py`）：LRU + TTL 1 小时，文档入库/删除自动失效，线程安全带命中率统计。

> 注意：当时文档写「压缩降低约 60%」是**规划值**，2026-09-17 用 231 题评测集实测规则模式**平均降约 21%**（96% 触发），60% 已证伪废弃——见 [11 篇数据口径](./11-开发规约与环境基线.md)。

### 2. 可运营层

- Token 监控（`token_tracker.py`）：逐调用记录输入/输出，超 8000 告警，按模型/接口统计；
- 反馈闭环（`feedback.py`）：1-5 分评分，≤2 分自动标记待优化，JSONL 持久化，管理端可标记已处理；
- DOCX 表格提取：表格自动转 Markdown 入库，避免表格信息在切片中丢失。

### 3. 用户数据层（v2.2.0）

- `chat_history.py`：会话 CRUD + 消息追加（分页）+ 跨会话搜索；存储分层 `sessions.json`（元数据，小而多变）+ `messages.jsonl`（正文，追加型）——**按读写特征选格式**而不是一刀切；
- `user_memory.py`：用户主动记录的笔记/偏好，JSONL + 标签分类；
- 所有历史/记忆 API 均需登录，数据按用户名目录隔离（`data/chat_history/{username}/`）；访客问答不落盘。

## 三、踩坑与修复：会话越权漏洞（v2.1.1，本篇最重要）

- **漏洞**：`session_id` 完全由客户端控制且未与身份绑定。即便开启认证，用户 A 拿到 B 的 `session_id` 即可通过 `/api/qa/chat` 等接口读取 B 的对话历史；访客模式更可访问任意会话。
- **修复**：新增 `_bind_session(session_id, user)`——已登录绑 `username:session_id`，访客统一 `anon:session_id` 前缀隔离；四个使用 session_id 的接口（chat / chat_stream / agent/react / clear）全部接入；返回给前端的仍是原始 session_id，**绑定对客户端透明，零前端改动**。

## 四、产出物

检索增强三件套 + Token 监控 + 反馈闭环；对话历史（7 个 API）与个人记忆（6 个 API）两个用户数据模块；前端评分组件、统计面板、反馈管理表格；v2.1.1 会话绑定修复。

## 五、教训与规约

1. **凡是客户端可控的 ID（session_id、doc_id、kb_id），必须与服务端身份/权限绑定后再使用**——这不是认证问题，是授权问题，认证开了也挡不住；
2. 上多用户功能前先做一遍「能不能读到别人的数据」威胁建模，比事后打补丁便宜得多；
3. 存储格式按读写特征选：元数据 JSON、追加正文 JSONL；
4. 「60%」这类规划值一旦写进文档就会被到处引用——**要么实测后写，要么标注「规划值未实测」**。
