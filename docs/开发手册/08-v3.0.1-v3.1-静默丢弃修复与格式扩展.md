# 08 · v3.0.1~v3.1.0 静默丢弃修复与格式扩展（2026-09-15）

> 目标：还一笔技术债——234 份语料里有 36 份因格式不支持被**静默跳过**，操作员看到「入库完成」却不知道这批文件从未进库。修复后顺势补齐 .doc/.xlsx 两个格式的零依赖解析。

## 一、先修「静默丢弃」（v3.0.1）

### 问题

`POST /api/knowledge/ingest` 扫描目录时，对非支持格式（`.doc`/`.xls`/`.xlsx`/`.wps`）以及解析后无内容的文件直接 `continue`——不告警、不计入返回体。真实语料 234 份中 **36 份**（31 `.doc` + 3 `.xlsx` + 1 `.xls` + 1 `.wps`）属此类。

### 修复原则：「提示但不动数据」

- 返回体新增 `unsupported` / `skipped_empty` 字段列出被跳过的文件名；`message` 追加 ⚠ 提示；分别打 WARNING 日志；
- 解析异常的文件同样归入 `skipped_empty`，不静默吞掉；
- **常量收敛**：扩展名清单此前在 `loader.py` / `knowledge.py` / `upload.py` 三处各写一份（漂移风险）——统一为 `SUPPORTED_EXTENSIONS` 单一来源；上传接口 400 报错同步列出支持格式；
- `tests/test_regressions.py` 新增 2 例锁定：混合目录必须显式上报、干净目录不得出现 ⚠。累计 **69 测试**。

> 这条修复是全项目「静默失败是头号敌人」主线的标志性节点：不改变行为（跳过仍跳过），但让跳过**可见**。

## 二、再补格式能力（v3.1.0）

### 通道探测先行（选型决策）

- 本机 Word 已装（`Office16/WINWORD.EXE`）但无 pywin32 → COM 通道放弃；
- LibreOffice / WPS 均未安装 → soffice 通道放弃；
- 结论：走**零依赖解析**路线，只引入 `olefile`（本来就是传递依赖，转显式声明）。

### .doc：OLE + FIB piece table（`loader._load_doc`）

- `olefile` 读取 OLE 复合文档的 `WordDocument` 流，解析 FIB **piece table**（CLX → PlcPcd），按片解码（8 位 cp1252 / 16 位 UTF-16LE）；
- 相比「整体猜编码」：更可靠，且**天然只取正文**、避开 FIB 头部等二进制结构；
- 实测：31 份全部提取成功、30 份首行即真实标题、语料内常见词命中 31/31；
- `.doc` 注册进 `SUPPORTED_EXTENSIONS` 后，批量入库与上传**自动放行**——v3.0.1 常量收敛的直接红利（仅改一处）。

### .xlsx：标准库 zip + XML（`loader._load_xlsx`）

- `.xlsx` 本质是 zip + XML：`zipfile` + `xml.etree` 解析，零外部依赖（无需 openpyxl）；
- 读 `sharedStrings.xml` 共享串表，逐工作表按行输出 `| 单元格 | 单元格 |`；解析 `workbook.xml` + rels 还原**工作表名**便于检索定位；
- 实测 3 份全部提取成功：「营销部的组织架构与责权」5039 字（职责 1–11 完整保留）；另两份实为**空白表单模板**（171/594 字），无检索价值——正好被审核打分器按「长度合理区」低分挂起，**零特判**。

### 已知局限（不掩盖）

- 纯文本粗提取，不还原表格与排版；
- 1 份 WPS 生成文件正文混有二进制噪点段，根因在文件流本身；
- **刻意不加启发式过滤器**：实测会误删真实表格（169 岗位评估表、196 招聘表单）——改由审核打分器按文本密度/结构完整度自动低分挂起。

### 测试

新增 6 例（.doc 4：注册表/控制符清洗/piece table 非复杂片/非 OLE 安全返回空；.xlsx 2：合成样本验证共享串/内联串/表名、注册表），**累计 75 测试全离线通过**。

## 三、产出物

显式上报字段 + 常量单一来源；`.doc`/`.xlsx` 支持（零新依赖）；6 个回归用例；「36 份静默丢失」问题闭环（补齐后全量入库 202 文档 / 2086 分片 / 0 失败，2026-09-17 实测口径）。

## 四、教训与规约

1. **静默跳过是最危险的「正常」**：功能测起来都对，只有对账时才发现少了一成半的语料。凡是 `continue` 跳过，必须显式上报；
2. 扩展名/格式类常量**单一来源**，三处手抄必然漂移；
3. 格式解析选型先探测环境通道（COM/soffice/纯库），再定实现路线；零依赖路线的可靠性来自「按格式规范读」而非「堆依赖」；
4. 新格式接入不要顺手加「智能过滤」——过滤器误删的损失远大于垃圾入库（后者还有审核流兜底）；
5. 联动设计优于特判：格式扩展 × 审核流（空白表单自动挂起）在两个独立版本各自成立，合并时零胶水。
