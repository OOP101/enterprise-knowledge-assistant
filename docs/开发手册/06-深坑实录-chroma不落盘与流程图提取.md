# 06 · 深坑实录：chroma 不落盘 与 流程图提取（2026-08-30，v2.5.1）

> 两个当天连环爆的深坑，也是全项目**面试/复盘价值最高**的两篇素材：一个关于「进程内验证的假象」，一个关于「二进制格式要按规范读」。

---

## 坑一：向量库 "Error loading hnsw index"（重启后检索全挂）

### 现象

Windows 本机服务重启后，检索报 `Error constructing hnsw segment reader`，全库不可用；但重启前一切正常，且数据「看起来都在」。

### 根因

- chromadb 1.3.x / 1.5.x 在 Windows 上的**后台压缩器不落盘向量段数据文件**——目录里只剩 `index_metadata.pickle`，段数据留在 sqlite 写入队列中尚未刷出；
- 数据本体没丢，丢的是「已可见的段文件」→ 重启加载残缺段报错。

### 诊断过程的关键弯路（本坑最有价值的部分）

- 进程内读回验证：collection count 正常、query 正常——**全是假象**；
- 原因：chroma 对同一路径**按进程缓存实例**，进程内再怎么查都是内存里那份活实例，根本没走到「从磁盘重新加载段」这条坏路径；
- 结论固化为铁律：**外部存储的状态必须跨进程验证**（起新进程/重启服务后再查），进程内「读回正常」不可信。

### 修复三层

1. **启动自愈**：`embedder.repair_chroma_segments()` 服务启动时清理半初始化段目录，chroma 自动从写入队列回填——实测 2089 块全部恢复且跨进程可读（2089 为当时历史口径，现库 2026-09-17 实测 2086）；
2. **版本锁定**：`requirements.txt` 锁 `chromadb==1.3.7` 并注明「升级前务必在目标机器验证段文件落盘」；
3. **重建脚本重写**：批量写入 100 条/批，顺带修掉空库 delete 报错、rmtree 自锁、缺 sys.path 三个问题；本轮重建 205 文档 / 2089 分片 / 0 失败（历史口径）。

### 升级注意（写进 CHANGELOG 的运维项）

- 批量上传期间不要并行跑 pytest（chroma 写锁冲突）。

## 坑二：流程图 docx 文本提取不到（3 份上传失败）

### 现象与根因

- 011/152/189 三份流程图文档入库后内容近乎为空/提取失败；
- 根因：流程图节点文字在**绘图文本框**（`w:txbxContent`）与 SmartArt（`a:t`）里，python-docx 的段落遍历根本读不到这层 XML。

### 修复

- `loader._extract_drawing_text()`：正文 <50 字符时按文档序提取文本框/SmartArt 文本，`mc:Choice`/`mc:Fallback` 去重（同一图形两份拷贝只取一次）；
- 实测三份恢复入库（110~226 字符/份，节点可检索），全库另有 8 份文档受益。

### 为什么阈值是 50 字符

正常文档正文远超 50 字，只有「图即全部内容」的流程图才会触发提取——**兜底逻辑带触发条件**，不影响正常路径性能。

## 同日两个连带补丁

1. **流程原文检索回退默认库**：「查看流程原文」原先按流程定义写死部门库（请假→hr），语料实际全在 default 库必然「暂未检索到」。修复：部门库不存在或未命中自动回退默认库，四流程实测全部命中；
2. **对话历史不显示 AI 回答**：后端存的角色名是 `assistant`，前端只认 `ai`——存储层一直正常，纯前端展示 bug。修复兼容两种角色名。**教训：前后端契约字段（角色名枚举）要有单一事实源**。

## 教练式复盘

| 维度 | 坑一 | 坑二 |
|------|------|------|
| 表象 | 重启后报错 | 文件提取为空 |
| 第一直觉 | 数据丢了 / 磁盘问题 | python-docx 有 bug |
| 真根因 | 压缩器不落盘 + 进程内缓存假象 | 文本在文本框/SmartArt XML 层 |
| 修复哲学 | 自愈 + 锁版本 + 批量重建 | 带触发条件的兜底提取 |
| 沉淀 | 跨进程验证铁律 | 按格式规范读二进制 |

## 规约

1. **外部状态（向量库/文件/配置）一律跨进程验证**，进程内读回不可信；
2. 升级存储引擎前先在目标机验证持久化行为，锁版本是可接受的工程决策；
3. 解析二进制格式（OLE/XML）先查格式规范按结构读，不要「整体猜编码」；
4. 兜底逻辑必须带触发条件 + 幂等去重，否则会把正常路径拖慢或重复处理。
