# 01 · v1.0 MVP 奠基（2026-08-05）

> 目标：用最小代价验证「企业制度文档 → 可问答知识库」的完整链路，且**没有 API Key 也能完整演示**。

## 一、阶段目标

1. 把 PDF / Word / Markdown 文档入库为向量知识库；
2. 支持单轮问答（带来源引用）与多轮对话（会话记忆 + 指代消解）；
3. 有 Key 走真实 LLM，无 Key 自动演示——链路任何时刻可跑。

## 二、关键动作与决策

| 决策 | 内容 | 为什么 |
|------|------|--------|
| 技术骨架 | FastAPI + LangChain（LCEL）+ ChromaDB + pydantic-settings | 生态成熟、单机可跑、配置类型安全 |
| 解析选型 | PyMuPDF（PDF）/ python-docx（Word）/ 纯文本 | 覆盖存量语料 95%+ 格式 |
| 切片参数 | chunk_size=500 / overlap=50 | 制度条款平均长度匹配，沿用至今 |
| **演示模式** | `DemoLLM`（关键词规则引擎）+ `DemoEmbeddings`（jieba 分词 + md5 稳定哈希，512 维） | 无 Key 离线可跑；md5 而非内置 `hash()`，规避 `PYTHONHASHSEED` 重启后向量错乱 |
| 自动降级 | Key 无效/过期自动回退演示模式 | 演示不中断 |
| Agent 雏形 | 意图分类（query/action/list）+ 两节点工作流 + mock 工具表 | 先把"问答 + 办流程"的产品形态立起来 |
| 会话记忆 | 进程内 dict，按 session_id 隔离 | 简单够用，多用户隔离留给 v2.1.1 补 |

## 三、产出物

- 模块划分沿用至今：`src/ingestion`（入库）/ `src/retrieval`（检索）/ `src/chains`（问答）/ `src/models`（LLM 工厂）/ `src/agent` / `src/memory` / `src/prompts` / `config`；
- 10 个基础 API（`/api/qa/ask`、`/api/upload`、`/api/knowledge/*` 等）；
- 基础单页前端（问答 + 上传入库 + 文档列表）。

## 四、教训与规约（本阶段定下）

1. **演示兜底是第一优先级**——这条决定了后来所有"离线可测"的红利；
2. Embedding 换实现必须**清库重建**（collection 维度创建时锁定）——本阶段尚未踩到，v2.5.1 两次反向踩坑后上升为铁律；
3. `hash()` 不能用于需要跨进程/跨重启稳定的场景（md5 稳定哈希自此成为演示向量实现）。
