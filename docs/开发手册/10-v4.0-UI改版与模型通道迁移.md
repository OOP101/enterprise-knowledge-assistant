# 10 · v4.0 UI 改版 与 模型通道迁移（2026-09-18）

> 目标：两件并行的事——前端「科技蓝」改版 P1 合入；LLM 通道从腾讯 TokenHub（额度耗尽）整体迁到阿里云百炼。迁移途中顺手抓出一个**依赖版本漂移导致的静默降级**。

## 一、UI「科技蓝」改版（P1 合入前端）

### 立项与设计

- 用户反馈：左侧功能列表与整体页面不美观，要求换配色、借鉴优秀开源项目；
- 对标 FastGPT / RAGFlow / MaxKB / Dify 提炼设计模式，产出 [UI改版需求文档](../UI改版需求文档.md)（P0~P3 分期）+ [静态视觉稿](../ui-mockup-v4.html)（内联 CSS 零依赖）；
- 设计 token 化：主色 **#2F6BFF 科技蓝**，绿色降级为纯状态色（成功语义），`--accent-weak` 承载选中态底色——**改主题只改 token 层，不逐处刷颜色**。

### P1 落地（当日合入，后端零改动）

- `style.css`：`:root` 重写为浅色 token；深色挂 `[data-theme="dark"]`（蓝灰调），旧 `[data-theme="light"]` 保留兼容别名；8 处硬编码绿 rgba(16,183,80,*) 全部替换（action-card 保成功语义改 #22B573 系）；`.nav-item.active` 加浅蓝底 + 3px 左竖条；新增 `.nav-badge` / `.dashboard-hero` / `.review-placeholder`；
- `index.html`：logo 换蓝渐变；导航新增「入库审核」入口（`data-min-role="admin"` + 待审徽章）；控制台顶部 hero（分时段问候 + 开始提问）；静态资源版本 `?v=6.0` 防缓存；
- `app.js`：主题默认翻转为 light（**存储兼容**：老用户存过 dark 不受影响）；`loadReviewBadge()` 拉 `/api/review/queue` 的 `counts.pending_review`（失败静默隐藏徽章——降级而非报错）；hero 按钮跳问答页。

### 验证链（前端改动的固定动作）

`node --check` 语法 → uvicorn 起服 200 + 5 个注入点探针 → **pytest 75 全绿（28s）**。UI 改动跑后端测试的原因：改动触碰了 app.js 的 API 层与视图挂载，回归成本 28 秒，值得。

## 二、模型通道迁移：TokenHub → 阿里云百炼

### 探针先行

- TokenHub key 额度耗尽，用户给两个新 key。实测探针结论：
  - `sk-ws-` 开头 = **阿里云百炼**（`dashscope.aliyuncs.com/compatible-mode/v1`，254 模型聚合工作区）可用；
  - `o1_` 开头对 API 端点 401——属 bailian CLI 脚本体系凭据，不是标准 API key，弃用；
- **同 base_url 下逐模型实测**（temperature=0）：

| 模型 | 耗时 | 结论 |
|------|------|------|
| deepseek-v3 | **1.5s** | 设为主模型 |
| qwen3.6-flash | 5.1s | 可用备选 |
| qwen3.7-plus | 6.5s | 可用备选 |
| kimi-k3 | 7.9s | 可用（思考模型） |
| qwen3.7-flash | 17.4s | 慢，避用 |
| GLM-5.3-Flash | 400 | 聚合区第三方模型需**单独开通产品**——换模型前先探针 |

- Embedding `text-embedding-v3` 可用（1024 维），但现库是 demo 512 维向量——**切换 embedding 必须全库重建**（[06 篇](./06-深坑实录-chroma不落盘与流程图提取.md)维度教训），挂起待定不擅切；
- 落盘：`.env` 先备份 `.bak-20260918` 再改 + `config/model_config.json` 同步（均在 .gitignore 内）。

### 顺手抓出的环境漂移 bug（本篇最有价值）

- **症状**：换 key 后回答「像假的」——延迟极短、内容模板化；
- **诊断**：`type(get_llm()).__name__` 返回 `DemoLLM` 而非 `ChatOpenAI`——项目**静默降级**了；
- **根因**：`.venv` 里 langchain-openai 被升到 1.4.2，其 import `langchain_core.exceptions.ContextOverflowError`（core 0.3.x 不存在）→ ImportError → `get_llm()` 按设计回退 DemoLLM——**降级机制工作正常，坏在没人告诉你它降级了**；
- **修复**：`pip install "langchain-openai>=0.2,<0.4"`（0.3.35）+ `requirements.txt` 锁范围；恢复后真实链路 1.1s 返回，pytest 75 全绿；
- **固化诊断规则**：怀疑模型不对时第一查 `type(get_llm()).__name__`——不是 ChatOpenAI 即已静默降级。

## 三、教训与规约

1. **同一个 base_url ≠ 同一套行为**：模型选择就是一个 `model` 参数，但开通状态/耗时/思考模式差异巨大——逐模型探针，实测数据说话；
2. **静默降级必须有探测手段**：设计上「降级保证可用」是对的，运维上「降级必须可见」也是必须的（v2.5 的 error SSE、本篇的指纹诊断，同一条主线）；
3. 依赖升级是**显式动作**不是副作用：`requirements.txt` 用范围锁（`>=0.2,<0.4`），换环境先 `pip show` 核对（见 [11 篇依赖矩阵](./11-开发规约与环境基线.md)）；
4. 切 embedding = 重建向量库，两个动作必须捆绑决策，不能只切一半；
5. 前端 token 化 + 静态资源版本参数（`?v=`）是低成本高收益的老练做法。
