# 09 · v3.1.1~v3.1.2 性能优化与冷启动（2026-09-18）

> 目标：两批性能治理——请求热路径去阻塞（v3.1.1）与服务冷启动 17s → 2.4s（v3.1.2）。共同方法论：**先测量定位，再动手改**。

## 一、请求热路径优化（v3.1.1）

四个「一直在交学费」的隐藏开销，逐个实测确认后修掉：

### 1. 查询缓存 get() 去掉同步落盘（🔴 热路径）

- 原实现每次 `get()`（命中/未命中/过期）都把整个缓存 JSON **全量序列化写盘**——读路径做同步磁盘 IO，恰恰抵消缓存收益；
- 改纯内存操作，持久化仅写路径（put / invalidate_kb / clear）执行；命中/未命中计数容忍重启丢失；
- 顺带接通 `settings.cache_size` / `cache_ttl`（原为死配置，一直用硬编码默认值——**配置接了没用上也是一种静默失败**）。

### 2. 流式接口不再阻塞事件循环（🔴 并发瓶颈）

- `qa.py::chat_stream` 在 async 函数里 `for` 迭代**同步生成器**——LLM 流式期间（检索/压缩/逐 token 均为同步 IO）整个事件循环被卡住，所有并发用户请求排队；
- 改 `iterate_in_threadpool` 在线程池中迭代；删除无调用方的死代码 `_iter_sse`（含阻塞式 `time.sleep`）。

### 3. LLM 实例按配置指纹缓存 + 请求超时

- 原 `get_llm()` 每次新建 `ChatOpenAI`——每实例独立 httpx 客户端，每次调用重新 TLS 握手（百毫秒级）且无连接复用；
- 改按配置指纹（base_url/key/model/温度/思考模式/超时）缓存，在线切换时指纹失效自动重建；新增 `LLM_TIMEOUT`（默认 60s）→ `request_timeout`，网络故障不再挂死。

### 4. 单轮问答省一次 LLM 改写往返

- 原 `ask()` 每次固定 LLM 改写（思考模型下 2~7s）；`rewrite_query` 加 `use_llm` 参数，单轮走规则改写（口语归一 + 同义词扩展，零网络开销）；
- 上下文压缩 LLM 摘要由逐片串行（N 片 = N 次网络往返）改线程池并行（≤4 并发）；修掉二次截断「字符数 vs Token 预算」单位不一致导致**永不触发**的问题；
- 清理 1.0 遗留死代码（`build_retrieval_qa` / `_condense_question` 等）；`/api/health` 的 mode 改读运行时模型配置。

**测试：75 例全离线通过，无行为回归。**

## 二、冷启动优化（v3.1.2）：17s → 2.4s

### 测量定位（`python -X importtime`）

`import serve.main` 累计 **18.1s**，两个大头：

1. `langchain_text_splitters` 的包 `__init__` **无条件连带导入** `sentence_transformers` + `transformers` + `torch`（合计 ~17s，占 94%）——切片器只在文档入库时用，问答链路完全不需要 torch，却每次启动都白扛一遍；
2. lifespan 里的 Embedding 维度校验触发 `chromadb` 导入（数秒），阻塞服务就绪。

### 修复（把重导入移出启动路径）

- `splitter.py`：改 `get_splitter()` 函数内**延迟导入**（torch 全家移出启动路径）；
- `upload.py` / `knowledge.py`：顶层 `split_documents` 导入移入使用处（首次入库时才付一次成本）；
- `templates.py`：6 个模块级 `ChatPromptTemplate` 改 **PEP 562 模块级惰性属性**——`langchain_core.prompts` 导入链实测 ~5s（同样连带 torch），而问答只用字符串常量；首次访问构建并缓存，既有 `from templates import xxx` 用法零改动；
- `main.py`：维度校验挪到后台 daemon 线程（异常仅记日志）。代价明示：启动后数秒内首个查询可能顺带完成 chromadb 导入——**用可接受的首查延迟换服务就绪**。

### 实测

`import serve.main` 18.1s → **1.4s**；临时端口冷启动到 `/api/health` 200 → **2.4s**。

## 三、教训与规约

1. **读路径禁止同步磁盘 IO**——缓存/配置/会话这类高频读，落盘只发生在写路径；
2. **async 函数里迭代同步生成器是隐形并发杀手**：单用户看不出问题，并发一来全部排队；
3. 重量级库（torch/transformers/chromadb）**一律延迟导入**：判断标准是「这条启动路径上到底用没用到」，而不是「项目里有没有装」；
4. `python -X importtime` 是启动优化第一工具：不测量就优化，大概率优化错地方；
5. 性能修复要连带修「死配置」「单位不一致」这类顺手可及的正确性问题，但**每次改动都要 75 例回归兜底**。
