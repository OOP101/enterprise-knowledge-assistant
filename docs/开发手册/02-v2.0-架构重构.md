# 02 · v2.0 架构重构（2026-08-12）

> 目标：从「演示完备、离线可跑」升级为「真实能力 + 专业架构」——把 1.0 里不可测试、不可扩展的部分全部重做。

## 一、为什么必须重构

1.0 暴露的三个结构性问题：

1. **全局单例 + 模块级 `@lru_cache` 互相 import** → 循环依赖、无法单测（想测检索就得真连向量库）、并发改共享实例（同一 retriever 改 `kb_id` 引发串库竞态）；
2. **BM25 跑在向量粗排候选集里** → 关键词召回被向量天花板锁死；
3. **流式是"拆字模拟"** → 看起来在打字，实际生成早已结束，长回答等待体验极差。

## 二、关键动作与决策

### 1. 依赖注入容器 + 端口抽象（本阶段最重要的资产）

- `src/core/container.py`：组合根装配，按需创建、单例缓存、支持 `container.override(key, fake)` 注入测试替身；
- `src/core/interfaces.py`：定义 `BaseReranker` / `BaseRetrieverPort` / `SessionMemoryPort` / `VectorMemoryPort` / `LLMProvider` 六类端口；
- 收益：多知识库多实例、测试注入 fake（后来 75 例离线测试全部受益于此）、模型热切换不改调用方。
- **刻意决策**：手写约百行容器，不上 DI 框架——规模不需要，可读性优先。

### 2. 检索链路升级

- BM25 从「向量子集二次检索」升级为**全量语料分片索引**（按 doc_id 分片 + 分段 IDF），索引按 `(kb_id, epoch)` 缓存、入库/删除即失效重建；
- Dense + Sparse 双路 → **RRF 融合**（`1/(K+rank)`，K=60，只依赖排名不依赖分数，天然融合异构量纲）；
- 可插拔 Reranker：BGE 本地 / Qwen 在线 / Demo 字符重合兜底，settings 一键切换。

### 3. Agent 与记忆

- LangGraph 多节点工作流：`intent_classifier → knowledge / action → memory_writer`；
- ReAct Agent：LLM `bind_tools` 自主多轮工具调用，无 LLM 自动回退规则 Agent；
- 长期向量记忆（Chroma 独立 collection）全链路接通：action 后 `remember`、QA 前 `recall`；LLM 真指代消解（失败回退原问题）。

### 4. 认证权限与评估

- JWT 手写 HMAC-SHA256 + `compare_digest` 防时序攻击；RBAC 三级（admin 全见 / user 部门白名单 + 公开库 + 个人授权）；
- 多知识库 CRUD（`enterprise_knowledge_<kb_id>` 每库独立 collection）；
- Eval 评估体系：hit_rate / precision / f1 + LLM-as-judge（CLI 与 API 双入口）。

### 5. 真流式 + 前端 + 部署

- SSE 推送 `sources → token → done`，**先推 sources** 让用户第一时间看到引用（产品体验关键决策）；
- 前端升级为 6 页控制台（控制台/问答/知识库/模型设置/用户管理/系统设置），深浅主题切换；
- Docker Compose + Nginx 部署方案预留。

## 三、产出物

- `src/core/`（container / interfaces / tracing）；全量 BM25 混合检索；LangGraph Agent；JWT+RBAC+多知识库；Eval；真流式；6 页前端；Docker 部署方案。

## 四、教训与规约

1. **串库 bug 是重构的直接导火索**：共享 retriever 单例被并发改 `kb_id` → 此后铁律「检索器按 kb 实例隔离，`kb_id` 构造期固定，缓存键必含 `kb_id`」；
2. BM25 缓存键必须含语料版本 epoch，否则入库后搜到旧数据；
3. RRF 用排名不用分数——异构检索融合的标准答案，面试高频考点（K=60 平滑头尾贡献）；
4. Eval 修过一个真 bug：runner 调了不存在的 `retriever.retrieve()` 一跑就崩——**"写了没跑通"的功能等于没有**，评估体系必须先跑通再谈指标。
