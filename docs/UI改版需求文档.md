# UI 改版需求文档 — v4.0「科技蓝」改版

> 立项日期：2026-09-18。目标：解决左侧功能列表与整体页面不够美观的问题，整体风格借鉴主流开源企业知识助手项目。
> 配套视觉稿：[docs/ui-mockup-v4.html](./ui-mockup-v4.html)（纯静态 HTML，可直接浏览器打开预览）。

---

## 一、现状问题

基于 `serve/static/`（index.html v5.2 / style.css 3.0 深色主题）的现状梳理：

| # | 问题 | 具体表现 |
|---|------|---------|
| 1 | 主色不合适 | 绿色 `#10B750` 占比过高（active 态、按钮、logo、边框激活色全部用绿），绿色大面积使用易显廉价、与"知识/科技"心智不符 |
| 2 | 深色为默认 | `color-scheme: dark` 默认深色，企业工具场景白天长时间使用，浅色更主流；且当前深色下层级（canvas/sidebar/surface）差异弱，页面发闷 |
| 3 | 侧边栏层次弱 | 8 个入口两组平铺，无徽章/计数/状态提示；active 态仅靠颜色区分，折叠态 60px 下无图标提示增强 |
| 4 | 内容区密度失衡 | 控制台 8 张统计卡 + 文档长列表直接堆叠，卡片视觉重量一致、无主次；面板标题/正文对比不足 |
| 5 | 缺设计系统 | 无统一间距/字阶 token，部分样式内联（如 `style="margin-top:16px"`），组件间圆角/阴影不一致 |

## 二、对标分析（开源项目设计语言提炼）

借鉴对象：**FastGPT、RAGFlow、MaxKB、Dify、AnythingLLM**（不逐像素抄，提炼共同模式）：

| 模式 | 说明 | 采纳 |
|------|------|------|
| 浅色为主 + 可切深色 | Dify/MaxKB/FastGPT 默认浅色，深色为可选项 | ✅ 默认改浅色 |
| 蓝色系主色 | 蓝色传达"专业/可信/知识"，与绿色系拉开差距 | ✅ 科技蓝主色 |
| 侧边栏「窄 + 分组 + 徽章」 | 分组标题弱化、入口带计数徽章（如审核队列待办数）、底部用户区 | ✅ 全采纳 |
| 内容区「主次分层」 | 首页放 1 个主行动区（开始提问）+ 少量关键指标，长列表进卡片/表格容器 | ✅ 控制台重排 |
| 中性灰画布 + 白色卡片 | 画布浅灰 `#F5F7FB`、卡片纯白、1px 边框 + 极浅阴影区分层级 | ✅ 全采纳 |
| 动效克制 | 仅 hover/切换 0.15~0.25s 过渡，无夸张动画 | ✅ 全采纳 |

## 三、设计系统（Design Tokens）

### 3.1 色彩（浅色为默认）

```css
:root {
  /* 品牌色：科技蓝 */
  --accent:        #2F6BFF;  /* 主色：按钮/active/链接 */
  --accent-hover:  #1F5AF6;
  --accent-weak:   #EBF1FF;  /* 主色弱底：选中项底色、标签底色 */
  /* 画布与表面 */
  --bg-canvas:     #F5F7FB;  /* 全局画布（浅灰蓝） */
  --bg-sidebar:    #FFFFFF;
  --bg-surface:    #FFFFFF;  /* 卡片 */
  --bg-hover:      #F0F3F9;
  /* 文字 */
  --text-1:        #1A2233;
  --text-2:        #5A6478;
  --text-3:        #98A1B3;
  /* 边框与状态 */
  --border:        #E6EAF2;
  --error:         #E5484D;
  --warning:       #F59E0B;  /* 保留琥珀色用于待办/低分 */
  --success:       #22B573;  /* 仅限状态点/成功提示，不再作主色 */
}
```

### 3.2 深色主题（保留，次级选项）

深色下主色提亮为 `#5B8AFF`（深底上对比更好），画布 `#0E1116`、表面 `#161B22`、边框 `#272E3A`——整体向蓝灰调，替代现在偏纯黑的配色。

### 3.3 其他 token

- 圆角：卡片 12px、按钮/输入框 8px、徽章 999px；
- 阴影：`0 1px 2px rgba(16,24,40,.04), 0 1px 3px rgba(16,24,40,.06)`（极浅双层）；
- 字体：保留 Geist + 系统中文回退；字阶 12/13/14/16/20；
- 间距：4px 基数，面板内边距统一 20px，卡片间距统一 16px（清理内联样式）。

## 四、侧边栏改版（重点）

```
┌──────────────────────────┐
│ ▣ 企业知识助手            │  品牌：logo 主色改科技蓝
│   智能知识问答中心         │
├──────────────────────────┤
│ 知识                      │  分组标题 11px 弱化
│ ⬡ 新对话          ⌘N     │  ★ 主行动入口置顶（借鉴 Dify）
│ ▤ 智能问答                │
│ 🗋 文档清洗        [2]    │  徽章：待处理数
│ ▦ 知识库管理       9      │  徽章：库数量
│ ✓ 入库审核        [5]    │  ★ 新入口：审核队列（v3.0 后端已就绪）
├──────────────────────────┤
│ 系统                      │
│ ⚙ 模型设置 ●已连接        │  状态点：模型连通性
│ 👥 用户管理               │
│ ◈ 系统测试                │
├──────────────────────────┤
│ [深/浅] · [折叠]          │  快捷区
│ ┌──────────────────────┐ │
│ │ 客 管理员 admin       │ │  用户卡：浅色弱底
│ └──────────────────────┘ │
└──────────────────────────┘
```

要点：

1. **active 态**：`--accent-weak` 浅蓝底 + 主色文字 + 左侧 3px 主色竖条，替代纯色块；
2. **徽章系统**：待办类（审核队列/低分反馈）用琥珀底计数，普通计数用灰底；
3. **新增「入库审核」入口**（admin 可见）：v3.0 审核流后端 API 已全就绪、前端页未做，本次在侧边栏先占位，点击进占位页提示"审核页开发中"——为 Phase 3a/3b 预留；
4. **折叠态**：60px 仅图标 + 徽章缩为角标，hover 出 tooltip；
5. 权限逻辑（`data-min-role`）与现有 JS 完全复用，不动。

## 六、约束与不改动范围

- **后端零改动**：所有 API、`app.js` 业务逻辑不动；仅 HTML 结构调整 + CSS 重写 + app.js 中少量"徽章计数"取数钩子（复用现有 stats 接口）；
- 兼容 Chrome/Edge 最新版即可（内网工具，不做 IE/旧浏览器适配）；
- 主题切换逻辑保留（localStorage `data-theme`），深色下逐一核对对比度（正文 ≥ 4.5:1）；
- 尊重 `prefers-reduced-motion`；
- CSS 版本参数升级 `?v=6.0`、HTML 里 JS 版本同步，避免缓存串版。

## 八、验收标准

1. 默认打开为浅色科技蓝主题，手动可切深色且对比度达标；
2. 侧边栏含分组/徽章/active 竖条/折叠 tooltip，审核占位入口 admin 可见；
3. 控制台主次分明：主行动区 + 指标卡 + 表格化列表；
4. 问答页用户/助手气泡可区分，输入框为容器式；
5. 全部 8 个视图无样式错乱；`pytest tests/` 保持 75 全绿（前端改版不影响后端）；
6. 旧版可回滚：git 单独提交，revert 即回滚。
